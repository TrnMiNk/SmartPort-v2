# UC024 — Quản lý danh mục cầu bến

**Status:** Completed (2026-11-19). Evidence: `docs/testing/uc024-uc026-evidence.md`. · **Module:** M2 · **Priority:** H · **Rollout:** Đợt 1
Source: `usecases.txt` lines 2542–2579. FR-BRT-01; NFR-CAP-01, NFR-SCA-01, NFR-USA-01.

## 1. Objective
Create and update the berth catalog (4 to 6 berths) with the technical attributes needed for planning.

## 2. Actors
- **Primary:** Điều phối viên.
- **Supporting:** Quản trị hệ thống.

## 3. Permissions
- View: `DIEU_PHOI_VIEN`, `BAN_QUAN_LY`.
- Create and update: `DIEU_PHOI_VIEN`.

## 4. Preconditions
- The user is logged in with M2 rights.

## 5. Postconditions
- **Success:** berth saved; before and after values audited; a new berth can be chosen in planning without a code change.
- **Failure:** unchanged.

## 6. Main flow
1. The coordinator opens "Cầu bến" and sees the list with current state.
2. The coordinator adds a berth or edits one.
3. The form shows: code, length, maximum depth, berth type (`CONTAINER` or `BULK`), available cranes, dangerous-goods permission, coordinates.
4. The coordinator saves (`POST /api/v1/berths` or `PATCH /api/v1/berths/:id`).
5. The API validates and saves.

## 7. Alternative flows
- **3a. Coordinates empty:** allowed; the berth then cannot be shown on the map (map is Đợt 2).

## 8. Exception flows
- **5a. Duplicate code or value ≤ 0:** refused with the field.
- **5b. Edit the length or depth of a berth with plans:** warning listing affected plans; the coordinator must confirm (spec 6a). Confirmation is a request flag, and the API lists the affected plans in the response.

## 9. Business rules
- **BR-1** Berth code is unique (`UQ_berths_code`).
- **BR-2** Length, depth and cranes are non-negative or positive as stated (`CK_berths_dims`).
- **BR-3** Dangerous-goods permission is per berth (BR-03 in UC-026).
- **BR-4** Operational status is `IN_SERVICE` or `OUT_OF_SERVICE`. Maintenance is a separate interval (UC-034, out of scope).

## 10. Acceptance criteria
- AC-1 A new berth appears in planning without a code change. **Passed** (integration: the berth is in `GET /catalog/berths` and `GET /berths` at once and can be checked by `POST /berth-plan-checks`; e2e: it is listed and chosen in the placement check). The planning screen itself (UC-028) is not built.
- AC-2 Two berths cannot share a code. **Passed** (integration: duplicate, same code in other case, and four simultaneous creations give one berth; e2e: error on the code field).
- AC-3 Editing a berth with plans warns and requires confirmation. **Passed** (integration and e2e: the 409 lists the affected plans, the confirmed save succeeds and is audited).

## 11. Assumptions and open items
| ID | Item | Rationale | Affected |
|---|---|---|---|
| A-1 | Berth count is 4 to 6 (spec). The API does not enforce a maximum; the business owner decides. | Specification says "(4–6)" as the expected size, not a rule. | Section 1 |
| A-2 | Coordinates use WGS84 degrees. | Standard for GIS; the specification does not state a datum. | Section 6 |
| A-3 | Legacy `berths.status` values are unknown; V2 uses `IN_SERVICE` and `OUT_OF_SERVICE` (schema A-2). | No legacy domain evidence. | BR-4 |
| A-4 | The berth name is optional on the form (the specification lists the code, not a name); it defaults to the code. | `berth_name` is required by the schema; the specification form has no such field. | Step 3 |
| A-5 | The operational status can be changed on edit (BR-4 names the two values, the form does not list it). Maintenance intervals stay UC-034. | Without it OUT_OF_SERVICE (UC-025 BR-3) could never occur. | BR-4 |
| A-6 | "Kích thước" in spec 6a means length and maximum depth. Plans affected are DRAFT, PENDING_APPROVAL and APPROVED ones. | The specification does not define "kích thước". | 5b |
| A-7 | Longitude and latitude are both given or both empty. Berth codes are letters, digits, hyphen or underscore, up to 20 characters, unique ignoring case. | A map position needs both; the schema allows 20 characters; the database collation ignores case. | 3a, BR-1 |
| A-8 | Reading needs `view` and changing needs `edit` on M2_BERTHS in the SRS matrix. That also lets warehouse staff and administrators read, which the specification does not list. | The matrix is the source for permissions (UC-005). | Section 3 |
