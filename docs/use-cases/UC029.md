# UC029 — Lưu kế hoạch cập bến và gửi phê duyệt

**Status:** Completed (2026-11-19) for the manual path; plans from the local optimizer keep their proposal reference and source (tested). Plans from an external AI provider do not exist (UC-027 has none), so that part is unverifiable. The manager's notice was measured at 81 to 149 ms (B1, `docs/testing/a2-b1-realtime-evidence.md`). Evidence: `docs/testing/uc029-uc030-evidence.md`.
Source: `usecases.txt` lines 2742–2780. FR-BRT-12, FR-BRT-06; NFR-ACC-02, NFR-SEC-04.

## 1. Objective
Submit a final draft for approval. The plan moves to `PENDING_APPROVAL`, the AI proposal and the coordinator's decision are kept, and the port manager is notified.

## 2. Actors
- **Primary:** Điều phối viên.
- **Supporting:** Ban quản lý (receives the notice; UC-030).

## 3. Permissions
- Submit: `DIEU_PHOI_VIEN`.

## 4. Preconditions
- A draft plan exists (UC-028) with a final placement.

## 5. Postconditions
- **Success:** plan `PENDING_APPROVAL` with `submitted_by` and `submitted_at`; status history row; in-app notification to `BAN_QUAN_LY`.
- **Failure:** plan stays `DRAFT`.

## 6. Main flow
1. The coordinator chooses "Lưu và gửi duyệt".
2. The API re-runs the placement check (UC-026).
3. If all rules pass (or overrides have reasons), the plan moves to `PENDING_APPROVAL`.
4. The API stores the AI proposal reference and the decision.
5. The API notifies the port manager role (D6).

## 7. Alternative flows
- **1a. Save as draft without submitting:** the plan stays `DRAFT` and can be edited.

## 8. Exception flows
- **2a. A rule fails without an override:** refused; the coordinator returns to UC-028 (`409 BUSINESS_RULE_VIOLATION`).
- **3a. Concurrent change:** `409 CONFLICT`; reload.
- **Another open plan exists for the voyage:** refused by `UX_bp_open_plan_per_voyage`.

## 9. Business rules
- **BR-1** Only a `DRAFT` plan can be submitted (status transition).
- **BR-2** Submission is refused if the placement check does not pass or lacks an override reason (`CK_bp_reviewed`).
- **BR-3** A voyage has at most one open plan (`PENDING_APPROVAL` or `APPROVED`).
- **BR-4** The AI proposal and the coordinator's final decision are both kept (FR-BRT-12).

## 10. Acceptance criteria
- AC-1 A plan with a passing check reaches `PENDING_APPROVAL`. **Passed** (integration, e2e): submitter and time recorded, status history, audit, voyage and queue unchanged, nothing approved.
- AC-2 The port manager receives the notice. **Passed:** `GET /notifications` shows it to users with the role and to nobody else; in the browser a manager who already has the page open sees the notice and the plan within 5 s without reloading (two-account scenario); the notice can be marked read.
- AC-3 No plan is saved with an unresolved violation. **Passed:** the check is repeated at submission inside the berth lock; a violation without an override reason is refused (409) and the plan stays a draft; missing data is never accepted; the database refuses a submitted plan with a failed check and no valid override (`CK_bp_reviewed`, migration test).
