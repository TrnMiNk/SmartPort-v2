# UC010 — Tạo hồ sơ tàu

**Status:** Completed (2026-11-18; evidence in `docs/testing/phase-a-b-evidence.md` §4) · **Module:** M1 · **Priority:** H · **Rollout:** Đợt 1
Source: `usecases.txt` lines 1976–2013. FR-VES-01; NFR-USA-01.

## 1. Objective
Create a vessel profile with its technical data and operator, so that arrival notices can refer to it.

## 2. Actors
- **Primary:** Điều phối viên (Coordinator).
- **Supporting:** Quản trị hệ thống.

## 3. Permissions (SRS matrix, enforced by the API)
- Create: `DIEU_PHOI_VIEN` (action `edit` on `M1_VESSELS`).
- Read only: `BAN_QUAN_LY`, `NHAN_VIEN_KHO_BAI`, `QUAN_TRI_HE_THONG`. They cannot create (403, audited as DENIED).
- `KY_THUAT_VIEN`: no access to M1.
- `DAI_LY_HANG_HAI` (external agent): can read only vessels operated by its own agents; cannot create.
- The administrator creating vessels is not allowed in V2 (the matrix gives the administrator view only); the specification's wording "có quyền tạo/sửa M1" is read through the matrix.

## 4. Preconditions
User is logged in and holds the create permission.

## 5. Postconditions
- **Success:** vessel saved (active), detail page shown, one `SHIP_CREATE` audit row.
- **Failure:** no data changed; the entered data stays on the form.

## 6. Main flow
1. The coordinator opens "Vessels & berths" and chooses "+ Add vessel".
2. The form asks for IMO, name, flag, vessel type, operator agent, LOA, beam, maximum draft, deadweight.
3. The coordinator saves (`POST /api/v1/ships`).
4. The API checks required fields, IMO format and uniqueness, dimensions above zero, and that the type and agent exist.
5. The API saves the vessel in one transaction with its audit row and returns it; the screen opens the vessel's detail page (with change history).

## 7. Alternative flows
- **4a. IMO of the wrong format or duplicate:** the error is shown under the IMO field (Vietnamese) and the user returns to step 3. Duplicate is `409` with `details.field = imo_number`; simultaneous duplicates yield exactly one vessel.

## 8. Exception flows
- **5a. Server or database error:** the error is shown and everything typed stays in the form; the user can retry.
- Unknown vessel type or agent: field error. Unknown fields in the body (for example `is_active`) are refused.

## 9. Business rules
- **BR-1** IMO is unique (`UQ_ships_imo`, plus a locked pre-check) and has exactly seven digits.
- **BR-2** LOA, beam, draft and deadweight are greater than zero, with at most two decimals, within the column size.
- **BR-3** Vessel type and operator agent come from the catalogs and must be active.
- **BR-4** Every creation writes an audit row with the new values.

## 10. Acceptance criteria
- AC-1 No two vessels with the same IMO. **Passed.**
- AC-2 Error messages are Vietnamese and clear, per field. **Passed.**
- AC-3 A valid vessel is saved and can be read back. **Passed.**
Evidence: `docs/testing/phase-a-b-evidence.md` §4.

## 11. Assumptions
| ID | Assumption | Rationale |
|---|---|---|
| A-1 | The IMO check digit is not validated, only the format. | The specification asks for format and uniqueness. A check-digit rule would be an added rule. |
| A-2 | Only coordinators create vessels. | SRS matrix: M1 "T" is only for the coordinator. |
| A-3 | `deadweight_t` holds "tổng trọng tải". The legacy `capacity` column may mean something else. | Not confirmed (schema A-1). |
| A-4 | The "detail page" is a dialog on the same screen, with the data and the change history. | Keeps the existing design; no separate detail route exists in the imported UI. |
| A-5 | `ship_code` is generated as `IMO` + the IMO number. | The column is required and unique; the IMO is already unique. |
| A-6 | Agents read only vessels whose operator is one of their agents. A vessel without an operator is invisible to agents. | UC-013 scope rule; the SRS gives agents no wider right. |

## 12. Demo scenario
1. Sign in as a coordinator, open Vessels & berths, add a container vessel. Expect its detail page with a "Created" history entry.
2. Add a second vessel with the same IMO. Expect the error under the IMO field.
3. Sign in as warehouse staff. Expect no "Add vessel" button, and a forced POST is refused with 403.
