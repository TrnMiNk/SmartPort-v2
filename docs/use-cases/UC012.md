# UC012 — Đính kèm và theo dõi thẩm định tài liệu hồ sơ tàu

**Status:** Analyzed · **Module:** M1 (dependency, decision D2) · **Priority:** M · **Rollout:** Đợt 1
Source: `usecases.txt` lines 2057–2097. FR-VES-04; NFR-CAP-02, NFR-USA-01.

## 1. Objective
Attach documents (PDF or image, up to 10 MB) to a vessel, or to a specific voyage, and track each document's review status and validity. Validity is used by UC-015.

## 2. Actors
- **Primary:** Điều phối viên (review and upload).
- **Supporting:** Đại lý hàng hải (upload for own vessels).

## 3. Permissions
- Upload: `DIEU_PHOI_VIEN`, `DAI_LY_HANG_HAI` (own agent's vessels only).
- Review (approve or reject): `DIEU_PHOI_VIEN`. Spec: "người có quyền cập nhật trạng thái thẩm định". Assumed coordinator (A-2).
- Download: same roles as upload.

## 4. Preconditions
- Vessel exists (UC-010). For a voyage document, the voyage exists (UC-013).
- User is logged in.

## 5. Postconditions
- **Success:** file stored, document row with `review_status = PENDING`, validity dates recorded if given, audited.
- **Review:** `APPROVED` or `REJECTED` with reviewer and time; a rejected document has a note and the agent is notified (in-app, D6).
- **Failure:** no file stored.

## 6. Main flow
1. The user opens the vessel (or voyage) and chooses "Đính kèm tài liệu".
2. The user selects a file and document type, optionally a voyage, and validity dates.
3. The API checks type and size (≤ 10 MB), stores the file under a generated key, and writes the row as `PENDING`.
4. A reviewer approves or rejects the document, with a note for rejection.
5. The API saves the review, audits it, and notifies the agent on rejection.

## 7. Alternative flows
- **4a. Rejection:** the agent receives an in-app notification asking for a new document.

## 8. Exception flows
- **3a. File larger than 10 MB or wrong format:** refused with the reason (`VALIDATION_FAILED`, `CK_sd_size`, `CK_sd_mime`).
- **3b. Validity end before start:** refused (`CK_sd_validity`).

## 9. Business rules
- **BR-1** File types: PDF, JPEG, PNG (`CK_sd_mime`).
- **BR-2** File size between 1 byte and 10 MB inclusive (`CK_sd_size`).
- **BR-3** A document is either standing (`voyage_id` empty, applies to the vessel) or voyage-specific (`voyage_id` set). Decision D2.
- **BR-4** Only reviewers change review status. The reviewer and time are required once reviewed (`CK_sd_review_fields`).
- **BR-5** A rejected document needs a note (`CK_sd_rejected_note`).

## 10. Acceptance criteria
- AC-1 A file larger than 10 MB is refused with a clear message. **Evidence:** `schema.test.js` "a document larger than 10 MB is rejected" and "exactly 10 MB is accepted" (boundary). Endpoint evidence pending.
- AC-2 The review status of each document is shown correctly. *(Schema enforces states. Endpoint and screen pending.)*
- AC-3 A voyage-specific document is stored against its voyage (D2). **Evidence:** `schema.test.js` "a voyage-specific document references a voyage".

## 11. Assumptions and open items
| ID | Item | Rationale | Affected |
|---|---|---|---|
| A-1 | **Decision D2:** documents are both vessel-level and voyage-level. Validity is stored per document. | The user chose minimum document management that supports voyage-specific documents and validity. | BR-3 |
| A-2 | Review is done by `DIEU_PHOI_VIEN`. | The specification names "người có quyền" without a role. | Section 3 |
| A-3 | File storage (where bytes live) is not decided. The row stores a `storage_key`. Storage design is a Milestone 2 item. | Not needed for the schema; needed before upload. | Section 6 |
| A-4 | The validity dates are `DATE` (no time). | Documents expire by day. Legacy used `DATETIME2`; see schema §1. | BR-1 |
| A-5 | Which document types are required for arrival is policy content (UC015 A-1). The catalog marks applicability only. | Required sets are not defined in the specification. | UC-015 |

## 12. Demo scenario
1. Upload a 2 MB PDF registration to a vessel. Expect status `PENDING`.
2. Approve it with validity dates. Expect `APPROVED`.
3. Upload an 11 MB file. Expect refusal.
4. Upload a voyage manifest for one voyage. Expect it attached to that voyage only.
