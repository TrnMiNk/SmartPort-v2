# UC013 — Tạo thông báo tàu đến

**Status:** Completed (2026-11-18; re-audited 2026-11-19, status unchanged): drafts (3a, A-6) and the automatic hand-off to UC-015 are implemented and tested. AC-4 (valid vessel in the queue within 5 s) measured in browsers: 77 to 144 ms (B1, `docs/testing/a2-b1-realtime-evidence.md`). Documents for validation are still inserted by SQL (UC-012 not built). Evidence: `docs/testing/uc013-uc015-uc020-evidence.md` §4. · **Module:** M1 · **Priority:** H · **Rollout:** Đợt 1
Source: `usecases.txt` lines 2098–2138. FR-VES-02, FR-VES-08; NFR-USA-01, NFR-PER-01.

## 1. Objective
Record that a vessel will arrive on a voyage, with declared ETA and cargo. Starts the validation (UC-015) and later the queue.

## 2. Actors
- **Primary:** Đại lý hàng hải, or Điều phối viên.

## 3. Permissions (enforced by the API)
- Action `notice` on `M1_VESSELS`: `DAI_LY_HANG_HAI` and `DIEU_PHOI_VIEN`. Port management, warehouse staff, administrator and technician cannot create notices (403, audited).
- An agent may announce only with an agent it is linked to, and only for vessels operated by its own agents; anything else is 403 (audited). Agents cannot set the priority class (it is `STANDARD`).
- A coordinator may announce for any active vessel and set the priority class.

## 4. Preconditions
User logged in; the vessel has a profile (UC-010) and is active (UC-011).

## 5. Postconditions
- **Success:** notice saved as `ANNOUNCED`, one status-history row (time, actor), one audit row, in one transaction.
- **Failure:** nothing saved.

## 6. Main flow
1. The user chooses "+ New arrival notice".
2. The form asks for vessel, voyage code, agent, origin port, declared ETA (entered in UTC+7), TEU, cargo type, service request, and (coordinator only) priority class.
3. The user submits (`POST /api/v1/voyages`).
4. The API validates the input, locks the vessel row, checks the vessel, scope, catalogs and duplicates.
5. The API saves the notice, the history row and the audit row.
6. **Not built in this slice:** hand the notice to automatic validation (UC-015). The notice stays `ANNOUNCED`.

## 7. Alternative flows
- **3a. "Lưu tạm":** keep the entered data in the browser only. **Not built.**

## 8. Exception flows
- **3b. Same vessel and voyage already announced:** `409` with the existing notice id; the screen shows the message on the voyage code. Also when two requests arrive together (one wins).
- **4a. Vessel inactive or without a profile:** `409` (`SHIP_INACTIVE`, `SHIP_NOT_FOUND`) with guidance.
- **4b. Agent outside its scope:** `403`.
- Invalid fields: `400` with field messages; unknown fields (for example `status`) are refused.

## 9. Business rules
- **BR-1** One notice per vessel and voyage code.
- **BR-2** Every status change writes history with actor and time.
- **BR-3** The ETA is the one declared by the agent. It is stored in UTC and shown in UTC+7; entered values without an offset are refused by the API.
- **BR-4** The notice, its history and its audit row are one transaction.

## 10. Acceptance criteria
- AC-1 Saved with status history (time, actor). **Passed.**
- AC-2 A duplicate vessel and voyage cannot be created. **Passed.**
- AC-3 An agent cannot announce for another agent's vessel. **Passed.**
- AC-4 The notice reaches the validation and queue stage within 5 seconds (with UC-015). **Not executed:** UC-015 is not built.

## 11. Assumptions
| ID | Assumption | Rationale |
|---|---|---|
| A-1 | "Lưu tạm" (draft) is a browser-only feature and is not built. | The specification says a draft is not an official notice. |
| A-2 | Agent scope: the voyage's agent must be one of the user's linked agents, **and** the vessel's operator must be one of them. | Refines the earlier proposal; stops an agent announcing for a vessel of a different agent. |
| A-3 | Priority class (`STANDARD`, `MAIN_LINE`, `REEFER_OR_HAZARD`) is the reading of "độ ưu tiên"; only coordinators set it. | Spec gives examples only (schema A-4). |
| A-4 | The coordinator notification of the validation outcome (UC-015 step 6) is in-app and belongs to UC-015. | Decision D6. |

## 12. Demo scenario
1. As an agent, announce a voyage for its vessel with ETA 2026-12-01 08:00. Expect it in the list as `ANNOUNCED`, ETA 08:00.
2. Announce the same vessel and voyage again. Expect the message on the voyage code.
3. As an agent, try another agent's vessel. Expect 403.
