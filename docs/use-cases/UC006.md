# UC006 — Quản lý danh mục nền

**Status:** Analyzed · **Module:** Chung (dependency, minimal) · **Priority:** H · **Rollout:** Đợt 1
Source: `usecases.txt` lines 1818–1859. FR-ADM-05; NFR-MNT-01, NFR-SEC-04, NFR-SCA-01.

## 1. Objective
Maintain reference catalogs used by M1 and M2: ship types, container types, shipping lines (agents), flag states and yard areas. For this delivery only the catalogs needed by M1 and M2 are in scope: ship types, document types, agents and ports. The administration screen is out of scope; rows are created by seed.

## 2. Actors
- **Primary:** Quản trị hệ thống.
- **Supporting:** none.

## 3. Permissions
- Read: any authenticated user (forms need the lists).
- Create, update, deactivate: `QUAN_TRI_HE_THONG`. Admin endpoints are out of scope; these are seeded.

## 4. Preconditions
- The administrator is logged in (UC-001).

## 5. Postconditions
- **Success:** the catalog entry is saved and immediately available to dependent forms; the before and after values are audited.
- **Failure:** the catalog is unchanged.

## 6. Main flow
1. The administrator opens a catalog group.
2. The administrator adds or edits an entry and saves.
3. The API validates type, uniqueness of the code within the group, and saves.
4. The API audits the change.

## 7. Alternative flows
- **3a. Deactivate an entry:** a confirmation is required (frontend). The entry is marked inactive, never deleted.

## 8. Exception flows
- **6a. Duplicate code within the group:** rejected with `VALIDATION_FAILED`.
- **6b. Deactivating an entry in use:** rejected with the number of referencing records (spec exception 3b). Enforced by foreign keys plus a service check.

## 9. Business rules
- **BR-1** Catalog entries are never physically deleted (spec).
- **BR-2** Codes are unique within their group (`UQ_ship_types_code`, `UQ_ports_code`, `UQ_agents_code`, `document_types.code` primary key).
- **BR-3** Ship type carries `cargo_class` (`CONTAINER` or `BULK`), used by berth matching (UC-026).
- **BR-4** `document_types.applies_to` (`SHIP`, `VOYAGE`, `BOTH`) defines whether a document is standing or voyage-specific (decision D2).

## 10. Acceptance criteria
- AC-1 A new entry appears in dependent forms without a code change. *(Design: lists read from the database. Evidence pending.)*
- AC-2 A duplicate code is refused. **Evidence:** unique constraints in `schema_migrations` tests (pending catalog-specific test).
- AC-3 An entry in use cannot be deactivated. *(Pending: service check not written.)*
- AC-4 Changes are audited with old and new values. *(Pending: no admin endpoint.)*

1. Seed the catalogs. Create a ship with a seeded ship type. Expect success.
2. Try a ship with an unknown ship type. Expect `VALIDATION_FAILED`.
