## 2. Finish the demo database (needs your password, done by you)
The demo accounts are created through the real API with a password that **you** type. It is read from a hidden prompt into an environment variable for one command and removed afterwards. It is not shown, stored or generated by anyone else.

```powershell
Set-Location <repo>\API
$env:SP_DB_NAME = 'SmartPortV2_DemoFinal'      # already created, migrated 0001-0008, catalog seeded
$sec  = Read-Host 'Demo password (12+ characters, throw-away)' -AsSecureString
$bstr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($sec)
try {
  $env:SP_DEMO_PASSWORD = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($bstr)
  node scripts/demo-data.js --confirm-disposable      # six accounts, ships, voyages, berths, plans, via the real API
} finally {
  [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($bstr)
  Remove-Item Env:SP_DEMO_PASSWORD -ErrorAction SilentlyContinue
}
node scripts/check-consistency.js                      # expect: 9 of 9 checks passed
```
The script stops if the database already holds berths, voyages or demo accounts, so it cannot be run twice by mistake.

## 4. A1: what changed
`API/src/db/schemaReadiness.js` compares `dbo.schema_migrations` with the migration files this code ships (version and SHA-256 checksum). The API stops before the listener and the ETA worker exist when a migration is missing (including a gap), has a different checksum, is unknown to the code (database newer), the table is missing or its metadata is invalid. Adding a migration file raises the requirement automatically. The check only reads; it never changes the schema, and its error contains no connection details. Verified on the real old databases `DemoRun2` and `Verify4` (read-only start attempts): both refused, naming 0006, 0007 and 0008.
