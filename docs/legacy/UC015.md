## 3. Preconditions and postconditions

**Preconditions** [doc]: the voyage notice was accepted by UC-013 or UC-014.

**Postconditions** [doc]:
- Success: voyage is `Chờ cập bến` (waiting for berth), in the queue, with a forecast ETA.
- Failure: `Thiếu hồ sơ` (missing documents) or `Từ chối` (rejected) is stored with its reason. The voyage is not queued and does not move to `Hồ sơ hợp lệ` or `Chờ cập bến`.

## 4. Flows

### Main flow (spec steps 1–6) [doc]
1. Check validity: required fields, IMO format, vessel not on the prohibited list, documents still valid.
2. Result is `Hợp lệ` (valid).
3. Call AI ETA prediction (UC-016).
4. Put the voyage in the berth-waiting queue by predicted ETA and priority.
5. Record status history: Đã thông báo → Hồ sơ hợp lệ → Chờ cập bến.
6. Notify the Coordinator.

Code [code]: `automaticVoyageValidation.afterIntake` calls `service.validate(voyageId, { actor: 'uc015-automatic' })`. Queue, history, and rollback behavior is described in the completion checkpoint [doc].

### Alternative flows
- **1a. Missing or wrong documents** → `MISSING_DOCUMENTS`. Agent is asked to resubmit. On resubmission, the flow returns to step 1 [doc]. Code: `afterDocumentSubmission` rechecks ANNOUNCED/MISSING_DOCUMENTS voyages for the same ship [code].
- **1b. Prohibited or restricted vessel, or expired documents** → `REJECTED` with reason; flow ends [doc]. Code: the completion doc records `REJECTED/DOCUMENTS_EXPIRED` for expired-only required documents [doc].

### Exception flow
- **3a. AI service does not answer within 10 seconds** → use the declared ETA, label it "chưa có dự báo AI" (no AI forecast), continue to step 4 [doc].
  - Code: `services/voyageEtaPrediction.js:37–38` uses `ETA_AI_TIMEOUT_MS`, default 10000 [code].
  - Code: `services/etaPredictionAdapter.js:27` `predictSafely` has a **default timeout of 1500 ms** [code].
  - **Conflict** (see section 10).

## 10. Doc-vs-code conflicts

1. **AI timeout.** Spec says 10 seconds. `voyageEtaPrediction` uses 10 seconds by default [code], but the shared `predictSafely` helper defaults to 1500 ms [code]. Which path UC015 uses in production needs confirmation.
2. **Acceptance status.** `FINAL_UC_ACCEPTANCE.md` line 15 shows PASS for a "scoped no-op" retry, and PARTIAL/BLOCKED for the full UC. Treat UC015 as **not verified**.
3. **Expired-document outcome.** The completion doc says the original expired-document REJECTED branch versus multiple document versions "remains unresolved" [doc]. The spec says expired documents give REJECTED (1b). Code returns REJECTED only for expired-only required documents; mixed cases return 503 [doc].
4. **Notification.** Spec step 6 requires notifying the Coordinator. P1 says SSE is not proof of delivery [doc]. Delivery is unverified.

## 11. Gaps

- Table and column names were not extracted. Needed before data design.

- No durable worker or outbox. A crash between intake commit and validation can leave a voyage as ANNOUNCED without a check [doc].
- No real AI integration. ETA forecasting is stubbed or adapter-based [doc].
- Notification delivery to Coordinator is unverified [doc].
- Agent-ownership path is refused, not implemented [doc].
